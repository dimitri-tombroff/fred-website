Fred shows an estimated energy and CO2e figure for each person, team, project, agent
and model. The figure serves to compare usages and to discuss frugality. It is an
estimate, never a measurement, and the interface labels it "≈". This paper describes
how Fred 5.x Weaver computes it, on what basis, and how far it can be trusted. The
exact constants and configuration rules are in Fred's architecture documentation:
the [footprint chapter](https://github.com/ThalesGroup/fred/blob/weaver/docs/architecture/07-footprint.md)
and its [reference appendix](https://github.com/ThalesGroup/fred/blob/weaver/docs/architecture/A14-footprint.md).

## 1. From a turn to a figure

Every agent run reports, for each model it used, how many tokens it read and
generated. Fred's Control Plane records these facts in a consumption journal. This
holds for agents running in their own pods and for the agent embedded in the Control
Plane. Nothing estimated is stored.

The estimate is computed from the journal each time a dashboard asks for a figure.
It combines three inputs: the tokens of each report, coefficients describing each
model, and a declaration of where each model source runs. A better coefficient or a
corrected declaration therefore changes every past figure as soon as it is deployed.

## 2. The method

Fred follows [EcoLogits](https://ecologits.ai), an open-source method maintained by
GenAI Impact that estimates the impact of one language-model request. A request's
footprint has four ingredients:

1. **GPU work.** A model generates its answer one token at a time. Each generated
   token costs energy that grows with the model's active parameters.
2. **The rest of the server and the building.** CPUs, memory and network run during
   the generation time. The datacenter's PUE (Power Usage Effectiveness) multiplies
   this IT energy to account for cooling and power distribution.
3. **The electricity.** Its carbon intensity depends on the country or the supply
   contract: about 35 gCO2e per kWh in Sweden, 41 in France, 458 on the world average.
4. **The manufacturing of the hardware.** Each request is charged a share of the
   servers' and GPUs' manufacturing, in proportion to the time it occupies them over
   a three-year lifetime.

Fred keeps EcoLogits' model as five coefficients per model and applies them to each
report of `output` generated tokens:

```text
ΔT    = time to first token + output × seconds per output token
kWh   = (output × GPU energy per output token + ΔT × server power) × PUE
gCO2e = kWh × grid intensity + ΔT × manufacturing CO2e per second
```

The model's size decides how many GPUs it occupies, hence its server power and its
manufacturing share. A catalogue is only accepted if these coefficients reproduce
EcoLogits' own result.

## 3. What is counted, and why

| Counted | Not counted |
| --- | --- |
| Tokens generated by the model | Tokens read by the model: prompt, history, documents, cached or not |
| Generation time, estimated from the model and the generated tokens | Training of the model |
| Electricity of the servers, times the PUE | Network and end-user devices |
| A share of the hardware's manufacturing | Document ingestion and embeddings |

EcoLogits charges inference to the tokens a model generates. Reading a prompt is done
in parallel and costs much less per token than generating one; providers also serve a
large part of repeated prompts from a cache. Counting read tokens like generated ones
overstated agentic turns by two to three orders of magnitude, because an agent re-sends
its whole context at each tool call.

Reading a long context is not free, however. EcoLogits accounts for it only through a
measured generation time, which Fred 5.x does not record yet. Fred therefore estimates
the generation time from the model and the generated tokens.

## 4. Who sets what

| Level | What it decides | Who changes it |
| --- | --- | --- |
| **Method** | Hardware and load assumptions: H100 GPUs, batches of 64 concurrent requests, server power, three-year lifetime, manufacturing footprint of servers and GPUs | Nobody in Fred: a new EcoLogits release |
| **Models** | The coefficients of each model Fred knows, derived from EcoLogits, and a default for the others | Fred maintainers, in a new Fred release |
| **Hosting** | Where each model source runs: the electricity's carbon intensity and the datacenter's PUE | The operator of each Fred instance, in its configuration |

An operator controls electricity and building, not hardware or load. This matters for
self-hosted models, as section 7 explains.

## 5. Declaring where a model runs

An operator declares the hosting of each model source configured in the instance:

```yaml
platform:
  model_footprints:
  - source_id: mistral          # a configured model source
    grid_gco2e_per_kwh: 35.26   # carbon intensity of the electricity
    pue: 1.16                   # datacenter power usage effectiveness
```

| Where the model runs | Carbon intensity | PUE |
| --- | --- | --- |
| A provider's API (Mistral, OpenAI, Google, Anthropic) | The country EcoLogits assumes for the provider | EcoLogits' value for the provider |
| A model deployed in a cloud project | The intensity the provider publishes for the region, or the country's mix | The PUE the provider publishes |
| A model hosted on premises | The country's mix or the supply contract's figure; in France, [ADEME's Base Empreinte](https://base-empreinte.ademe.fr/) | The datacenter's measured annual PUE |
| Unknown | Not declared | Not declared |

A source without a declaration is estimated with the world-average electricity mix
and a PUE of 1.54, the industry average reported by the
[Uptime Institute's 2025 survey](https://intelligence.uptimeinstitute.com/resource/uptime-institute-global-data-center-survey-2025).
A model missing from the catalogue is estimated with a default model. In both cases
the figure is flagged as a fallback, which tells the operator what to declare.

## 6. A worked example

A RAG agent on Mistral Medium answered a question in eight model calls. Its tokens
were:

- **161,949 tokens read.** It re-read a research article piece by piece, and 93 % of
  these tokens were served from the provider's cache.
- **1,911 tokens generated.**

Its model source, Mistral's API, is declared with 35.26 gCO2e/kWh and a PUE of 1.16:

```text
ΔT    = 1,911 × 0.1039 s                                    = 198.5 s
kWh   = (1,911 × 3.785e-7 + 198.5 × 0.009375 / 3600) × 1.16 = 0.00144 kWh
gCO2e = 0.00144 × 35.26 + 198.5 × 0.000651                  = 0.051 + 0.129 = 0.18 g
```

The tokens read do not enter the result. Almost three quarters of it is manufacturing:
on a low-carbon grid, the hardware a request occupies weighs more than its
electricity. Before Fred 5.x adopted this method, the same turn was estimated at
246 g, by charging all tokens with a factor scaled from a life-cycle analysis.

## 7. Limits

- **An order of magnitude.** On the same 400-token answer from Mistral Large 2,
  EcoLogits gives 0.044 g and
  [Mistral's own life-cycle analysis](https://mistral.ai/news/our-contribution-to-a-global-environmental-standard-for-ai)
  gives 1.14 g, a factor of about 25. Fred follows EcoLogits because its method is
  open and reproducible, not because it is known to be closer to reality.
- **An estimated time.** EcoLogits' default generation time can exceed the real one
  several times over. In the example, the measured time was 19.6 s instead of
  198.5 s. With the measured time, the estimate would be about four times lower.
- **Fixed hardware.** The hardware and load assumptions describe a well-loaded
  server. A self-hosted model on GPUs used far below a batch of 64 carries a larger
  manufacturing share per answer than estimated.
- **The agent's context is not counted.** An agent that calls tools re-sends its
  context at each call. The tokens it re-reads are not counted, even when the
  provider recomputes them.
- **Aliases move.** A model name such as `mistral-small-latest` follows the model
  the provider currently serves under it. A new catalogue can change the
  coefficients behind the same name.

## 8. Open questions

- **Reference:** which reference should Fred stand behind, given the factor of 25
  between EcoLogits and a provider's life-cycle analysis? Should it show a range?
- **Context:** should the input tokens that are actually recomputed carry a small
  coefficient of their own, although no published source provides one?
- **Generation time:** should Fred record the measured generation time, which
  changes the estimate about fourfold?
- **Self-hosted hardware:** which data about self-hosted inference (GPU type, load)
  should an operator be able to declare?
- **Presentation:** at what level of aggregation should the figure be shown, so that
  it informs choices without being read as a judgment on a person?
